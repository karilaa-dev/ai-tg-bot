# Application state machines

Follow a row from left to right to trace a normal operation. The last column identifies the event or guard that matters on a retry, cancellation, crash, or late callback. These are application workflows across requests, asynchronous events, and stored records. A state can be a TypeScript variant, a database predicate, a held resource, or a state supplied by an external runtime.

## A conversation turn

| Owner | States and transitions | Recovery and observable behavior |
| --- | --- | --- |
| [Telegram batching](../src/bot/batching.ts) and [intake](../src/bot/intake.ts) | Text collects until its timer fires. An album alternates between collecting and held while media arrives. Flush starts an acceptance attempt, which can retry, complete or be cancelled. | Stop and shutdown resolve pending input. Update IDs deduplicate redelivery at acceptance. |
| [Web submission](../src/web/chat-service.ts) | New request → preparing attachments → accepting → accepted. Repeated requests join an in-flight submission or find its durable result. | User, thread and request ID identify the submission. The finally path accounts for prepared files even when a concurrent request wins. |
| [Durable turns](../src/db/repos/turnRuns.ts) and [status definitions](../src/db/turnLifecycle.ts) | Accept → queued. Claim the FIFO head → running. Save a deliverable result → awaiting_delivery. Finish → succeeded or failed. A queued or running turn can be cancelled. An expired active owner can be interrupted. | One active turn per thread. Owner and lease fence writes. A running stop sets a request on the row. Delivery competes atomically with cancellation. The first terminal write wins even if the same owner calls back twice. |
| [Coordinator](../src/ai/threadTurnCoordinator.ts) | Recover → accept/wake → drain a thread → claim/execute → drain again or go idle. Shutdown closes intake and waits for owned work. | Queued work survives process restart. A leased fork/compact barrier waits for earlier work and freezes a history snapshot. A lost lease aborts the operation. |
| [Turn engine](../src/ai/agentTurnEngine.ts), [shaper](../src/ai/shaper.ts) and [budget](../src/pi/turnBudget.ts) | Thinking, tool calls, tool results and assistant text update the current draft. The answer takes over from the thinking preview. Completion, failure, a budget limit or stop ends execution. | Finalization distinguishes delivery from model execution. Tool activity has its own running and terminal outcomes. |
| [Telegram draft pump](../src/telegram/draftStreamer.ts) | Idle → waiting for rate limit or sending → idle. A flood wait queues another attempt. Stopping aborts previews. | Coalesces frames while sending. A newer frame supersedes the waiting one. Topic fallback and native Stop use the active draft identity. |
| [Finalizer](../src/ai/turnFinalizer.ts) and [delivery](../src/ai/responseDelivery.ts) | Running → cancelled or delivering → confirmed, rejected or unknown. Delivery bookkeeping can still be pending after Telegram replies. | Persist the actual send outcome on retry. A model failure can have a successfully delivered explanation. An ambiguous send must not be sent again automatically. |
| [Activity sync](../src/db/repos/turnActivity.ts) and [worker](../src/ai/turnActivity.ts) | Dirty → leased → synchronized, or released for retry. Run status determines the desired working reaction. | Generation, lease and desired state must still match after the remote call. A newer change dirties the record again. |
| [History](../src/web/repository.ts) and [read cursors](../src/db/repos/threadReads.ts) | Queued, generating, stopping, delivering and interrupted are projections of the turn, lease and stop timestamp. Reading advances a per-user/thread message cursor. | A reply awaiting attachment delivery fences cursor advancement. Fork ancestry limits what is visible. |

## Conversation and account workflows

| Owner | States and transitions | Recovery and observable behavior |
| --- | --- | --- |
| [Threads and forks](../src/application/conversations.ts) | Create/link → active → archived. Fork creates a child at the barrier snapshot and copies the Pi session. | A failed fork archives its partial child and attempts to remove its Telegram topic. An archived thread can be forked. |
| [Thread titles](../src/bot/threadTitles.ts) and [repository](../src/db/repos/threads.ts) | Placeholder → claim attempt → generated or retry. Explicit rename supersedes generation. Topic synchronization is tracked separately. | Conditional writes protect manual titles. |
| [Compaction](../src/application/compactionAction.ts) and [execution](../src/application/conversations.ts) | Queued → running → succeeded or failed. A stale queued/running action reads as interrupted. | Repeated requests in a process join the same operation. Serialized progress writes preserve the order of the final outcome and heartbeats. |
| [Schedules](../src/db/repos/schedules.ts) and [scheduler](../src/scheduling/runner.ts) | Enabled → due → occurrence accepted → advanced to the next interval or disabled for a one-shot. The scanner waits between passes and drains on stop. | Occurrence acceptance and advancing the schedule share a transaction. Busy threads defer work. Revoked access disables the schedule. |
| [Onboarding](../src/bot/onboarding.ts) | Prompt → wait for timezone → save, retry invalid input, or finish after the attempt limit. | grammY owns suspension and replay. |
| [Telegram web login](../src/web/chat-auth.ts), [sessions](../src/web/session-store.ts) and [access](../src/access/control.ts) | Start → browser-bound transaction → consume callback → verify identity/access → create session. Logout/revocation removes the session. | The transaction is single-use and expires. Access is checked again on authenticated requests. Rotation replaces the previous session in one transaction. |
| [Codex device login](../src/web/codex-login.ts) | Settled → authorizing → committing → success/error. Cancellation or expiry during authorization drains the attempt. | Only the current authorization can publish a code. Stop waits for a bounded credential commit. Public status carries device-code fields only while pending. |
| [Credential store](../src/pi/codexCliCredentials.ts) | Read from file → refresh → persisted or memory-only if saving fails. Delete suppresses provider reads. A later update can use the file again. | Exclusive writes and credential fingerprints protect a newer login or external refresh. The status check reports the backing credentials. |
| [Process startup and shutdown](../src/main.ts) and [web server](../src/web/server.ts) | Initialize stores and services → poll/serve → stop intake → drain operations and release resources. | Partial startup uses the same cleanup path. Repeated web shutdown callers share the stop promise. |

## Files, tools, and model runtime

| Owner | States and transitions | Recovery and observable behavior |
| --- | --- | --- |
| [Telegram files](../src/bot/files.ts), [ingest](../src/files/ingest.ts) and [audio](../src/audio/transcription.ts) | Download → transcribe audio if needed → prepare/index → attach. File extraction tracks pending, ready, failed or source-only. | Job cancellation stops outstanding work. A failed preparation cleans up its unattached row. Saved transcripts can be reused. |
| [Multipart input](../src/web/chat-upload.ts), [budget](../src/web/upload-budget.ts) and [recovery](../src/web/upload-recovery.ts) | Parse part headers/body → next part or epilogue. Reserve → write → settle bytes → release lease. An expired or abandoned lease enters recovery. | Ownership is recorded before creating artifacts. Under a row lock, recovery preserves attached files and queues removal of orphans. Failed removals back off and retry on the owning storage instance. |
| [Local store](../src/files/localStore.ts), [resolver](../src/files/resolver.ts) and [download pool](../src/web/download-pool.ts) | Stage → publish and verify, repair, or revoke. Read from eligible sources until verified, consent required, or unavailable. Download waits → admitted → released. | Revocation fences late publication. A user has one download slot or FIFO queue entry. Cancelling a waiter frees its entry. |
| [Outgoing files](../src/files/outgoingFiles.ts), [buffers](../src/files/outgoingBuffers.ts) and [delivery](../src/ai/responseDelivery.ts) | Reserve/prepare → ready → dispatch. A Telegram send is pending, confirmed, rejected or ambiguous. Byte reservations can commit or release. | Source availability and send acknowledgement are separate facts. A definitive group rejection can retry files individually. |
| [Office visual review](../src/office/validation.ts) | Failed structural checks block progress. Valid bytes need page previews, then reviews. A failed review requests changes. Passing every page and check approves delivery. | The tool exposes `review_state` alongside `approved`. State belongs to the source hash. Reopening a page preserves its review. |
| [Pi sessions](../src/pi/runtime.ts) and [thread bridge](../src/pi/threadBridge.ts) | Create/load a thread runtime → use → retire → dispose. A turn acquires and releases command activity around tools. | Eviction observes ownership. Turn-scoped tools and caches reset across turns. Credential replacement refreshes the shared model registry in place. Shutdown releases the remaining cached sessions. |
| [Provider circuit](../src/pi/circuit.ts) and [stream router](../src/pi/provider.ts) | Closed → open/cooldown → one half-open probe → closed or reopened. Buffered events become a committed Codex stream or yield to fallback. | Older probes cannot settle a newer circuit generation. Fallback is allowed before meaningful output is committed. |
| [Image generation](../src/pi/imageExtension.ts), [usage](../src/pi/usage.ts) and [tool completion](../src/ai/tools/finishResponse.ts) | Image generation accumulates events until a completed image/response or failure. Usage accumulates per call. Finishing a response validates the selected text, files and optional visualization. | Image completion and usage arrival can differ. Cancellation, malformed results and failed file validation preserve a recoverable tool outcome. |
| [E2B runtime](../src/e2b/threadRuntimeManager.ts), [file restoration](../src/e2b/telegramFileMaterializer.ts) and [template release](../src/e2b/templateRelease.ts) | Resolve a sandbox mapping → connect/create → use → idle/pause. Published sites extend the active window. Materialization records available/error. Release resolves, builds if needed and validates a versioned image. | Mapping identity, activity leases and resume consent govern reuse. A later turn can retry a failed restore. |
| [Browser sessions](../src/browserUse/runtime.ts) and [downloads](../src/browserUse/download.ts) | Resolve profile → open session → use thread-owned tabs → close, or retain a pending stop for retry. Idle expiry and maximum session lifetime trigger cleanup. | Session rollover and profile persistence are tied to the owned session. Tab snapshots and selected downloads carry identities across tool calls. |
| [Sandbox commands](../src/e2b/sandboxCommandExecutor.ts) and [output capture](../src/e2b/commandCapture.ts) | Start command → stream bounded stdout/stderr → exit, timeout or abort. | Command outcome carries exit status and output truncation. Thread activity leases keep the sandbox available during work. |
| [Database transactions](../src/db/index.ts), [schema upgrades](../src/db/uuidMigration.ts) and [user search](../src/db/userSearch.ts) | Begin → execute → commit or roll back. Initialization upgrades legacy identifiers and rebuilds dependent references. Dirty search keys → normalized keys. | Transactions fence partial upgrades. Normalization checks the identity observed before publishing, so a concurrent rename can be retried. |
| [Memory store](../src/memory/optmem/databaseStore.ts), [commands](../src/memory/optmem/index.ts) and [recall worker](../src/memory/optmem/recall.ts) | Notes can be added or forgotten. Summary blocks progress from pending to compressed and can become pending again. Recall waits for startup, then one batch result at a time. | A revision guards summary writes after invalidation. Timeout, cancellation, worker exit or an unexpected reply settles the outstanding recall. |

## Browser workflows

| Owner | States and transitions | Recovery and observable behavior |
| --- | --- | --- |
| [App entry](../src/web/client/app.tsx), [chat gate](../src/web/client/chat/gate.tsx) and [account requests](../src/web/client/chat/api.ts) | Load route → check session → signed in, signed out, forbidden, or unreachable. Logout invalidates requests for the previous account. | Reconnection and retry recheck the session. A late check or response must not restore an old identity. |
| [Composer and drafts](../src/web/client/chat/drafts.ts) and [chat shell](../src/web/client/chat/chat-app.tsx) | Edit → submit → sending → failed/retry or accepted → confirmed in history. A first message can wait for thread creation. | Request identity ties retries to a message. Draft ownership and session closure govern discard. |
| [Conversation](../src/web/client/chat/conversation.tsx) and [request state](../src/web/client/request-state.ts) | History polling and read acknowledgements each run a request, optionally with a follow-up. Thread actions include stop, fork and compact. | Refreshes reconcile with the selected thread and viewport. A retried acknowledgement advances only to an eligible message. |
| [Search](../src/web/client/chat/search.tsx), [thread list](../src/web/client/chat/use-threads.ts) and [admin](../src/web/client/admin-app.tsx) | Query → debounce/load → results, empty, or failed → paginate/retry. Select a result to preview or navigate. | Query/thread identity bounds results. Background refresh can preserve previously loaded rows. |
| [Schedules](../src/web/client/chat/schedules.tsx), [memories](../src/web/client/memories.tsx) and [access list](../src/web/client/allowed-users.tsx) | Select/create → edit/save or confirm deletion → submit → settle/retry. Access can be granted and revoked. | Pending actions retain the selected record. Failed mutations can surface an error alongside loaded data. |
| [Preferences](../src/web/client/chat/preferences.tsx), [settings sync](../src/web/client/chat/settings-sync.ts) and [timezone prompt](../src/web/client/chat/time-zone-prompt.tsx) | Load confirmed settings → optimistically edit → serialize patches → confirm or roll back. Timezone selection may be prompted or dismissed. | Reconcile settings and language with the active account. |
| [Attachment controls](../src/web/client/file-attachment.tsx), [fetch/cache](../src/web/client/attachments.ts) and [image display](../src/web/client/authenticated-image.tsx) | Automatic load or explicit request → fetching → ready, consent required, or failed → retry with selected consent. | Request identity, caller cancellation and object-URL lifetime govern display and cleanup. |
| [Device login panel](../src/web/client/codex-connection.tsx) | Poll status → start/cancel operation → display code, success, expiry or error → allow a new attempt. | Mutations take precedence over old polls. The server owns credential activation. |
| [Usage view](../src/web/client/usage.tsx) and [pricing](../src/web/usage-pricing.ts) | Load a period → display report or retry. Pricing refreshes once for concurrent callers and retains the last good catalog on failure. | Freshness, retry time and an outstanding refresh determine what the client sees. |
| [Service worker](../src/web/pwa/service-worker.js) | Install a revision's precache → wait for old clients → activate → serve that build's static assets. | The browser owns activation. The worker retires earlier caches on activation and restricts cache lookup to the build manifest. |

Binary UI controls such as expanded/collapsed disclosures, clipboard feedback, selected tabs and theme preference keep their state at the component. Parsing and rendering algorithms also have local states, including Markdown fences, table rows, regex captures and multipart delimiters. Their owners are the [Telegram renderer](../src/telegram/render.ts), [table converter](../src/telegram/compactTables.ts), [regex matcher](../src/memory/optmem/regex.ts) and multipart reader above.
